AWS Certified AI Practitioner (AIF-C01) Final Review Notes

tip

Every model-evaluation metric, prompt pattern, foundation-model concept, SageMaker tool, AWS AI service and responsible-AI guideline the AIF-C01 exam actually tests — organised the way the exam's five domains are weighted, not alphabetically. No prior ML experience assumed.

  • Total Time: 90 minutes
  • Passing Score: 700 / 1000
  • Exam Fee: $100 USD

1. AI & ML Fundamentals​

Types of Machine Learning​

TypeWhat It Does
Supervised learningLabelled data (input →\rightarrow→ target). Classification (discrete label) or regression (continuous value). Examples: spam detection, house-price prediction.
Unsupervised learningNo labels — model finds structure. Clustering (K-means), dimensionality reduction (PCA, SVD, t-SNE), association rules.
Semi-supervisedSmall labelled set + large unlabelled set. Cheaper than full labelling.
Self-supervisedModel generates its own labels from the data (predict next token, masked word). Foundation of LLM pre-training.
Reinforcement learning (RL)Agent learns from rewards and penalties in an environment. Uses: games, robotics, trading, fine-tuning LLMs (RLHF).
Transfer learningStart from a pre-trained model and fine-tune on your task. Less data, less compute, better results than training from scratch.

Data Labelling & Data Types​

  • Structured data: Rows/columns (tables, spreadsheets). Easy to feed classical ML.
  • Semi-structured: JSON, XML, logs. Has some schema but not rigid.
  • Unstructured: Free text, images, audio, video. Needs feature extraction or deep learning.
  • Time-series: Ordered observations over time. Forecasting, anomaly detection.
  • Labelling:
    • Amazon SageMaker Ground Truth: Human labellers + active learning.
    • Amazon Augmented AI (A2I): Human review of ML predictions.

Model Fit: Bias vs. Variance​

Total Error=Bias2+Variance+Irreducible Noise\text{Total Error} = \text{Bias}^2 + \text{Variance} + \text{Irreducible Noise}Total Error=Bias2+Variance+Irreducible Noise

ConceptDefinitionSymptom
BiasError from oversimplified assumptions — model can't capture the pattern.Underfitting: high train & test error.
VarianceError from over-sensitivity to training-set noise.Overfitting: low train error, high test error.
Bias-variance tradeoffRaising model complexity cuts bias but raises variance.—
  • Fixes for underfitting: More features, more complex model, less regularisation, train longer.
  • Fixes for overfitting: More data, simpler model, regularisation (L1/L2L_1/L_2L1​/L2​, dropout, early stopping), ensembles.

Neural Network Architectures​

ArchitectureUse Case
Feedforward (MLP)Tabular data, simple classification/regression.
Convolutional Neural Network (CNN)Image and video. Convolutions learn spatial features. Examples: ResNet, EfficientNet.
Recurrent Neural Network (RNN)Sequential data — time series, old-style NLP. LSTM/GRU handle long dependencies.
TransformerSelf-attention across a sequence. Foundation of modern LLMs (GPT, Claude, Llama, Nova, Titan). Enables parallel training at scale.
GAN (Generative Adversarial Network)Generator vs. discriminator. Produces realistic images, synthetic data.
Diffusion modelGradually denoise random input to produce images / audio. Backbone of Stable Diffusion, DALL-E.

2. Generative AI Fundamentals​

Foundation Models (FMs) & LLMs​

  • Foundation model: Large model pre-trained on broad data, adaptable to many downstream tasks via prompting, fine-tuning, or RAG.
  • LLM: Foundation model for natural language (GPT, Claude, Titan, Llama, Nova).
  • Multimodal: Accepts/emits multiple modalities (text+image+audio+video\text{text} + \text{image} + \text{audio} + \text{video}text+image+audio+video). Nova, Claude, GPT-4o.
  • Open-source vs. proprietary: Llama, Mistral (open) vs. Claude, GPT (proprietary API-only). Tradeoff: control + cost vs. capability + speed to ship.

Embeddings & Vector Databases​

  • Embedding: Dense vector representing semantic meaning of text/image/audio. Similar items have similar vectors (cosine similarity).
  • Embedding models: Titan Embeddings, Cohere Embed, Sentence-BERT.
  • Vector database: Stores and searches embeddings. AWS options:
    • Amazon OpenSearch Service (with k-NN)
    • Amazon Aurora (pgvector)
    • Amazon Neptune Analytics
    • Amazon DocumentDB
    • Amazon MemoryDB
    • Amazon RDS for PostgreSQL (pgvector)
    • Amazon Bedrock Knowledge Bases (managed)
  • Use cases: Semantic search, recommendation, RAG grounding, clustering.

Tokenisation & Context Windows​

  • Token: Chunk of text the model reads/emits. Roughly 0.75 words in English.
  • Context window: Max input + output tokens per call (e.g. 200K for Claude 3.5/4, 1M for some Nova models).
  • Cost: Billed per-input-token + per-output-token. Longer prompts →\rightarrow→ higher cost.

Dimensionality Reduction​

  • PCA (Principal Component Analysis): Linear method. Projects high-dimensional data to fewer dimensions while preserving variance. Used for visualisation and noise reduction.
  • SVD (Singular Value Decomposition): Matrix factorisation; foundation of PCA, recommendation systems, latent-semantic analysis.
  • t-SNE / UMAP: Non-linear visualisation of high-dimensional data.

3. Foundation Models & Prompt Engineering​

Customisation Approaches — Lightest to Heaviest​

ApproachWhen to UseCost
Prompt engineeringChange the prompt to steer the model. No training. Instant iteration.Lowest
RAG (Retrieval-Augmented Generation)Inject retrieved context from your data (via vector DB) so the model grounds its answer. Keeps data fresh.Low
Fine-tuningContinue training on labelled examples so the model adopts your style / format / domain. Use when prompt engineering hits a ceiling.Medium–High
Continued pre-trainingFurther train on unlabelled domain corpora. For specialised languages/industries where the base model is weak.High
Train from scratchRarely worth it outside research/hyperscale. Custom architecture or data modality.Highest

Prompt Patterns​

Foundation Patterns​

  • Zero-shot: Just the task description. "Classify this review as positive or negative:"
  • Few-shot / in-context learning: Include 2–5 labelled examples in the prompt.
  • Instruction: Explicit, imperative directions. "Summarise in three bullets. Use plain language."
  • Role / persona: Assign identity: "You are a senior tax advisor answering a client."
  • Contextual: Paste relevant docs, then ask the question against them (RAG baseline).
  • Style / tone: Specify voice: "Reply in the tone of a 19th-century letter."

Reasoning Patterns​

  • Chain-of-Thought (CoT): "Let's think step by step." Forces the model to show reasoning. Boosts math/logic accuracy.
  • Self-consistency: Sample multiple CoT completions, take the majority answer. Reduces variance.
  • Tree-of-Thought (ToT): Explore multiple reasoning branches, back up on dead ends.
  • ReAct: Interleave reasoning with tool/action calls. Foundation of agentic flows.
  • Reflection: Ask the model to critique its own answer and revise.

Structural Patterns​

  • Output structuring: Demand JSON, XML, markdown tables. Combine with schema validation on output.
  • Template prompting: Reusable skeleton with placeholder variables.
  • Prompt chaining: Split work across multiple prompts: summarise→extract→classify\text{summarise} \rightarrow \text{extract} \rightarrow \text{classify}summarise→extract→classify.
  • Active prompting: Model dynamically selects which examples/tools to use. Adaptive.
  • RAG integration: "Using the documents below, answer:..." Retrieve-then-generate.

Inference Parameters​

ParameterWhat It Controls
TemperatureRandomness. 0=deterministic0 = \text{deterministic}0=deterministic, 1=creative1 = \text{creative}1=creative. Low for code/extraction, high for brainstorming.
Top-p (nucleus)Sample from the smallest set of tokens whose cumulative probability ≤p\le p≤p. 0.9 is typical.
Top-kConsider only the kkk most-likely next tokens.
Max tokensCap on output length. Stops generation regardless of content.
Stop sequencesStrings that end generation when produced. Useful for streaming/structured outputs.
Presence/frequency penaltyDiscourage repeating tokens already seen — reduces looping.
tip
  • "Make output more creative" →\rightarrow→ Raise temperature or top-p.
  • "Make output deterministic for evaluation" →\rightarrow→ Temperature 0.
  • "Model keeps repeating" →\rightarrow→ Frequency/presence penalty.
  • "Model too long-winded" →\rightarrow→ Lower max tokens + explicit instruction.

4. Amazon Bedrock​

Fully managed service to access foundation models via a single API. No infrastructure to provision. Usage-based pricing (per token) or Provisioned Throughput (hourly commitment). All data stays in your account — AWS never uses your prompts to train base models.

Model Families​

  • Amazon Nova: Amazon's own frontier multimodal FM family: Nova Micro (text-only, fastest), Lite, Pro, Premier, plus Nova Canvas (image) and Nova Reel (video).
  • Amazon Titan: Text generation, embeddings, image generation. Lower cost, good for enterprise use cases.
  • Anthropic Claude: Claude Haiku / Sonnet / Opus. Strong reasoning and long context.
  • Meta Llama: Open-weight FMs in multiple sizes.
  • Mistral, Cohere, AI21, Stability AI: Additional specialised models.

Bedrock Capabilities​

FeatureWhat It Does
Invoke APISend a prompt, get a completion (streaming or batch). Same API shape for every model.
Knowledge BasesManaged RAG. Point at S3; Bedrock chunks, embeds (Titan or Cohere), stores in OpenSearch Serverless / Aurora / Neptune Analytics / Pinecone / Redis, and handles retrieval at query time.
AgentsMulti-step reasoning + tool calling. Define action groups (Lambda functions or OpenAPI schemas) + a knowledge base. Bedrock plans, executes, and returns the final answer.
GuardrailsContent filters (sexual / violent / hate / insults / misconduct), denied topics, word filters, sensitive-info filters (PII redaction), grounding checks, prompt-injection detection.
Custom modelsFine-tune a supported base model on your data (JSONL) or run Continued Pre-training. Access customised weights via Provisioned Throughput.
Model EvaluationCompare models on your data: automatic metrics (accuracy, BLEU, F1) or human evaluators via Ground Truth / A2I workflows.
Provisioned ThroughputHourly/monthly commitment that reserves capacity (in model units) for predictable latency. Required for custom fine-tuned models.
Prompt ManagementVersioned prompt templates and prompt flows. Deploy and A/B test prompts without code changes.
tip
  • "Enterprise wants to chat with its own documents" →\rightarrow→ Bedrock Knowledge Bases (RAG).
  • "Block the model from answering questions about X" →\rightarrow→ Guardrails denied topics.
  • "Model must refuse to output PII" →\rightarrow→ Guardrails sensitive-info filter.
  • "Need predictable latency under a heavy load" →\rightarrow→ Provisioned Throughput.

8. Model Evaluation Metrics​

Classification​

MetricFormula / MeaningWhen to Favour
AccuracyTP+TNTP+TN+FP+FN\frac{TP + TN}{TP + TN + FP + FN}TP+TN+FP+FNTP+TN​. % predictions correct.Balanced classes.
PrecisionTPTP+FP\frac{TP}{TP + FP}TP+FPTP​. Of those we said positive, how many really were.False positives expensive (spam filters, fraud).
Recall (sensitivity)TPTP+FN\frac{TP}{TP + FN}TP+FNTP​. Of all actual positives, how many we caught.False negatives expensive (disease, fraud).
F1 scoreHarmonic mean of precision and recall.Imbalanced classes.
AUC-ROCArea under ROC curve. Threshold-independent ranking quality.Need a single score that works across thresholds.
Log lossPenalises confident wrong predictions.Probabilistic classifiers.
Confusion matrixTable of TP/FP/TN/FNTP/FP/TN/FNTP/FP/TN/FN per class.Multi-class diagnosis.

Regression​

  • MAE (Mean Absolute Error): Average absolute difference between predicted and actual. Same units as target.
  • MSE (Mean Squared Error): Average squared difference. Penalises large errors more.
  • RMSE: MSE\sqrt{\text{MSE}}MSE​. Same units as target. More interpretable than MSE.
  • R2R^2R2 (coefficient of determination): Fraction of variance explained by the model. 1=perfect1 = \text{perfect}1=perfect, 0=no better than mean0 = \text{no better than mean}0=no better than mean, negative = worse than mean.

Text Generation​

MetricWhat It MeasuresBest For
ROUGERecall-based n-gram and sequence overlap with reference.Summarisation.
BLEUPrecision-based n-gram overlap with reference.Machine translation.
METEORWeighted precision + recall + synonym matching.Translation, summarisation.
BERTScoreSemantic similarity using BERT embeddings.Any generation — captures meaning, not just word overlap.
CIDErConsensus-based n-gram similarity (TF-IDF weighted).Image captioning.
PerplexityHow uncertain the model is predicting the next token. Lower is better.Language modelling.
tip
  • ROUGE is recall-weighted (did we capture the reference?).
  • BLEU is precision-weighted (is what we produced in the reference?).
  • BERTScore captures meaning — our output can have zero word overlap yet still score high if it's semantically equivalent.
  • Accuracy lies when classes are imbalanced →\rightarrow→ switch to F1 or AUC-ROC.

9. Responsible AI​

AWS Responsible AI Dimensions​

DimensionWhat It Means in Practice
FairnessModel performs equitably across demographic groups. Measure with SageMaker Clarify bias metrics (DPL, CDD, DI, DAR).
ExplainabilityUnderstand why the model decided. Clarify SHAP values; partial dependence plots.
RobustnessResists adversarial input and distribution shift. Monitor with Model Monitor.
Privacy & SecurityProtect training and inference data. KMS encryption, VPC endpoints, PII redaction, Bedrock Guardrails.
GovernanceDocument datasets, models, training runs. SageMaker Model Cards, Model Registry, lineage tracking.
TransparencyUsers know they're interacting with AI, model strengths and limitations are published (AWS AI Service Cards).
VeracityOutputs grounded in reliable sources. RAG with Knowledge Bases, Guardrails grounding checks.

Bias Types & Detection​

  • Sampling bias: Training data not representative of the real population (geography, demographics, time).
  • Measurement bias: Features recorded differently across groups.
  • Algorithmic bias: Model amplifies patterns in the data.
  • Confirmation bias: Humans labelling data reflect their assumptions.
  • SageMaker Clarify: Detects bias pre-training (data) and post-training (predictions) with metrics like Class Imbalance, Demographic Parity, Disparate Impact, Conditional Demographic Disparity in Labels.

Explainability Techniques​

  • SHAP (Shapley values): Per-feature contribution to a single prediction. Local explainability. SageMaker Clarify supports this.
  • Partial Dependence Plots (PDP): Show marginal effect of a feature on model output. Global view.
  • LIME: Approximate a complex model locally with a simpler surrogate. Not AWS-specific.
  • Feature attribution drift: Model Monitor tracks whether the features driving predictions change over time.

Generative AI Risks & Mitigations​

  • Hallucination: Model invents plausible-sounding but wrong facts. Mitigate with RAG, grounding checks, Guardrails.
  • Prompt injection: Adversarial instructions smuggled into user input. Mitigate with Guardrails prompt-injection filter, strict system-prompt boundaries.
  • Toxic / biased outputs: Guardrails content filters, human-in-the-loop via A2I, red-team evaluation.
  • Training-data leakage: Model reveals sensitive training examples. Use differential privacy, Bedrock (which does not train base models on customer data).
  • Copyright/IP: AWS offers IP-indemnification for Amazon Titan / Amazon Nova / Claude output under specific conditions. Review service terms.

10. Security, Compliance & Governance​

Identity & Access​

  • AWS Identity and Access Management (IAM): Users, groups, roles, policies (JSON). Always prefer IAM roles for workloads (SageMaker notebooks, Lambda, EC2) over long-lived access keys.
  • Principle of least privilege: Grant only the minimum permissions required. Use managed policies as a starting point, then scope down.
  • Resource-based policies: Attach to S3 buckets, KMS keys, SageMaker endpoints to control cross-account access.

Data Protection​

ServiceRole in AI Workloads
AWS Key Management Service (KMS)Encryption keys for S3 training data, EBS volumes, SageMaker artifacts, Bedrock custom-model weights. Customer-managed keys give full control.
AWS Secrets ManagerStore API keys, DB credentials, third-party LLM keys. Automatic rotation.
Amazon MacieDiscover and protect sensitive data (PII, credentials) in S3 before you ship it to a training job.
Amazon InspectorVulnerability scanning for EC2, Lambda, container images (ECR). Catches CVEs in your inference stack.

Audit & Compliance​

ServiceWhat It Does
AWS CloudTrailRecords every AWS API call. Management events free; data events (S3 object-level, Bedrock Invoke logs) optional. Critical for auditing who invoked which model with which prompt.
Amazon CloudWatchMetrics, logs, and alarms for model endpoints, training jobs, Bedrock usage.
AWS ConfigTracks resource configuration and compliance. Rules like 'SageMaker notebooks must have root access disabled', 'Bedrock models must have Guardrails attached' (custom rules).

12. Storage​

  • Amazon S3: Object storage. Primary data lake for ML training sets, model artifacts, Knowledge Base sources. Integrates natively with SageMaker, Bedrock, Glue, Athena, Redshift Spectrum.
    • S3 features for ML: Versioning (roll back bad data), lifecycle rules (tier old experiments), Object Lock (compliance retention), event notifications (trigger retraining on new data).
  • Amazon S3 Glacier: Archive storage classes (Instant Retrieval, Flexible Retrieval, Deep Archive). Use for training-data retention, audit-log archives, compliance-mandated retention.

15. Networking & Content Delivery​

  • Amazon VPC: Isolated virtual network. SageMaker training jobs, endpoints, and notebooks can run inside a VPC with no internet egress. Bedrock supports VPC Endpoints (PrivateLink) so prompts never traverse the public internet.
  • VPC Endpoints: Gateway (S3, DynamoDB — free) and Interface / PrivateLink (SageMaker, Bedrock, most services) keep traffic on the AWS backbone.
  • Amazon CloudFront: CDN with 700+ edge locations. Cache inference results for public models, serve a chat-bot web front-end with low latency, protect origins with AWS WAF.

16. Management & Governance​

  • Amazon CloudWatch: Metrics (endpoint invocations, latency, errors), logs (SageMaker training output, Bedrock Invoke logs), alarms (on model drift or cost spikes), dashboards.
  • AWS CloudTrail: Who invoked which Bedrock model, who edited which SageMaker endpoint. Management events free; data events (e.g. Bedrock Invoke) optional + charged.
  • AWS Config: Track resource configuration over time. Write a custom rule like 'all Bedrock agents must have a Guardrail attached'.
  • AWS Trusted Advisor: Best-practice checks. Flags idle SageMaker endpoints, underutilised RIs, unassociated Elastic IPs.
  • AWS Well-Architected Tool: Review workloads against the six pillars plus the Machine Learning Lens and Generative AI Lens for AI-specific guidance.

17. Cost Management​

  • AWS Cost Explorer: Visualise and forecast AI spend by service, tag (e.g. project: rag), account.

  • AWS Budgets: Thresholds on cost or usage. Alert when a Bedrock-heavy project trends over budget; can trigger SCPs to stop new spend.

  • Bedrock pricing model: Per-token on-demand (default) vs. Provisioned Throughput (hourly commitment, required for custom fine-tuned models).

  • SageMaker cost levers: Spot training (up to 90% off), right-size inference instances, Serverless Inference for bursty traffic, shut down notebooks when idle, Savings Plans for long-running endpoints.

  • Free Tier: SageMaker Studio: 250 hrs/month ml.t3.medium for 2 months; limited Bedrock and Comprehend free usage.

    tip
    • "Cut training cost on fault-tolerant jobs" →\rightarrow→ SageMaker Spot training.
    • "Predictable inference latency at scale" →\rightarrow→ Provisioned Throughput (Bedrock) or real-time endpoints with Auto Scaling.
    • "Pay nothing when no traffic" →\rightarrow→ SageMaker Serverless Inference.
